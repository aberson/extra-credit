Why this shape

Two findings from reading the source drove the design.

  • The saved settings file pins every limit. Raising an existing cap (20 for counting, 100 for Dry Math) would need a version 3 file and an upgrade of your real profiles file. Every harder choice is therefore a new setting with a default, and today's settings, pages and answers stay exactly as they are.
  • Pictures past 20 do not fit a page. Loose dots and ten-frames above 20 overflow one printed page, so counting goes higher through new pictures: tens rods and ones, dots in rows of ten, tallies in stacked rows. Numerals alone (comparison, equations, Number Bonds) simply go to 100.

Phase timeline

Five tracks, built one step at a time in order.

Each code step gets an independent code review and one full check after it merges. Steps share the same core files, so they run in ID order.

  1. Levels and arithmetic

    Steps 39-45

    Challenge and Expert levels from today's settings; three-digit sums, bigger × and ÷, remainders; mixed-up and offset grid headers.

    Afterwards: npm --prefix frontend run build then npm --prefix frontend run manual:print and try Dry Math, Operation Grid and an Expert packet with the fictional profiles.

  2. Numbers to 100

    Steps 46-49

    Number Bonds within 50 and 100 (plus "every problem carries or borrows" from 10 up), Wow equations to 100 with near-miss wrong answers and optional carrying, comparing numerals to 100.

    Afterwards: npm --prefix frontend run manual:print and Create each new range with its answer key.

  3. Clocks

    Steps 50-51

    Clock Explorer's first setting: half and quarter hours, then five-minute and any-minute times on a larger minute dial with minute marks.

    Afterwards: npm --prefix frontend run manual:print and print one page of each clock time step.

  4. Pictures past 20

    Steps 52-54

    Tens-and-ones pictures to 50 and 100, Wow dots to 50 in rows of ten, tallies to 50 in three rows. Last, because they carry the most print risk.

    Afterwards: npm --prefix frontend run manual:print and print each new picture page on Letter and A4.

  5. Levels reach the new practice, then your review

    Step 55 · HR1

    Harder, Challenge and Expert draw on everything above (table under HD6); then one screen review of every new choice and of the five packet levels.

    Afterwards: npm --prefix frontend run manual:print, set Pages to 8 with all families ticked, and make one packet per level.

Agent defaults

Defaults worth your eyes. Reference by ID to tweak.

HD1 Five levels: Easier, Medium, Harder, Challenge, Expert

What
Medium stays the default; Challenge and Expert are new.
Why
Two more rungs give room above today's Harder without renaming what you already use.
Tweak
Number or names of levels, or the default level.

HD6 Which practice each level uses (Step 55)

What
Harder adds mixed-up 10 × 10 grids, Number Bonds and Wow equations within 50, numeral comparison to 100, half and quarter hours. Challenge: three-digit sums without carrying, two-digit × one-digit, 12 × 12 mixed grids, Number Bonds and Wow equations within 100, Wow dots to 50, tens and ones to 50, five-minute times, tallies to 50. Expert: three-digit carrying, three-digit ÷ one-digit, remainders, offset headers (6-15), within 100 with every problem carrying, tens and ones to 100, any-minute times, powers.
Why
Each level rises by kind as well as by size, and every family keeps a choice that fits large print.
Tweak
Move any cell up or down a level, or change the hint wording (Harder "Numbers to 100, plus times tables, half and quarter hours, and longer words"; Challenge "Numbers to 1,000, plus two-digit × one-digit, five-minute times, tallies to 50 and independent writing"; Expert "Numbers to 1,000, plus powers, three-digit carrying, remainders, any-minute times, tallies to 50 and independent writing"). HR1 keeps or adjusts it.

HD5 One screen review after Step 55

What
No review between tracks; HR1 checks every new choice and the five levels on screen. Physical printing goes to M1, the children's own reactions to M2.
Why
Seventeen code steps with a review after each track would stall the phase; the waiver mirrors P6.
Tweak
Ask for a review after a specific track, for example after arithmetic.

HD7 "Every problem carries or borrows" in Number Bonds only from 10 up

What
Within 5 offers only Without and Include, because no page can be filled where every problem carries.
Why
The app never offers a choice that cannot make a page; the same rule hides Wow carrying below 50.
Tweak
Offer it everywhere and refuse within 5 before Create instead.

HD2 HD3 HD4 How the build stays safe

What
Each family gets its own new limit beside the existing ones, which never change (HD2); today's choices produce identical pages and answers (HD3); steps run in ID order with picture modes near the end (HD4).
Why
Raising the shared limits would silently widen tallies, ten-frames and earlier settings; identical output keeps every saved packet seed and test fingerprint valid.
Tweak
Reorder tracks (for example clocks first).

R1(a) R1(b) R1(c) R2 R3 R4 Working rules for every step

What
Packet code only spreads defaults (R1a), names new choices in packet rows (R1b) and keeps your saved harder choices out of Random packets until Step 55 (R1c); one wording owner per choice list (R2); no saved value above its limit (R3); an oversized step is split (R4).
Why
They keep labels truthful, packets predictable and each step reviewable in one sitting.
Tweak
Usually none; say which rule you want relaxed and why.

Not in this phase

Cut on purpose.

  • Sentence Builder changes (writing was already right).
  • A version 3 settings file or any upgrade of your profiles file.
  • Subtraction grids, mixed-operation grids and stacked column arithmetic.
  • Tallies or dot pictures to 100 (they do not fit four to a page).
  • Saving packets between visits; the packet stays session-only.
