Extra Credit

A local-first, open-source tool for making personalized activity sheets that grow with a family.

The outcome

A parent sets up a child profile once, chooses a worksheet and a few options, previews it, and prints a one-page activity plus an optional answer key. Profiles and generated content stay on the family computer. V1 supports the complete setup-to-print path for ages four through eight and uses deterministic reviewed templates, so correct math never depends on a model or network service.

Port clarification: the host and port solve different problems. The app binds to private loopback host 127.0.0.1; dev-observatory has reserved collision-free ports 4310 for the built app/API and 4311 for Vite development.

Scope boundary

Now: V1

  • Dry Math
  • Two Whats and a Wow
  • Sentence Builder
  • Count, Compare & Make
  • Reusable local profiles
  • Ages 4–8 setup-to-print support
  • Letter and A4 printing
  • Name, interests, and line-art toggles

Later: separate plans

  • Explicitly enabled runtime AI experiment
  • Mini Mission activity
  • Reviewed packs for ages 9+
  • Additional languages or curricula
  • Accessible tagged-PDF export

Outside V1

  • Public hosting and cloud sync
  • Accounts, analytics, ads, or tracking
  • Scores, assessment, or progress history
  • Schedulers and unattended generation
  • Child-facing online sessions

No login, PIN, encryption layer, or secrets. Filesystem permissions protect the stopped file and loopback blocks network peers; while the app runs, other local processes/users can reach its API, so the plan requires stop-after-use guidance for shared or untrusted machines.

Agent-defaulted choices — confirmed

The operator confirmed all ten defaults on 2026-08-22, with D2, D3, and D9 revised first. Each stable card retains its rationale and a future amendment example.

Agent-defaulted · confirmed

D1 — Loopback and fixed ports

Bind 127.0.0.1:4310; use 127.0.0.1:4311 for Vite; allow no v1 runtime override.

Why: loopback prevents access from network peers by default, while observatory-reserved fixed ports make launchers, tests, and documentation reproducible. It is deliberately not presented as an OS-account boundary.

Change later: D1 -> allow a documented runtime port override in v2

Agent-defaulted · changed & confirmed

D2 — Capability-first profiles

Store age, explicit math capabilities, writing mode, review date, and interests. V1 has no avoid-topics field.

Why: one “math level” cannot safely choose counting representation, equality, operation, number range, and writing support; the removed field is not required for the first release.

Change later: D2 -> add a separately reviewed topic-exclusion feature

Agent-defaulted · changed & confirmed

D3 — Narrow validated age band

Support the complete U.S.-English setup-to-print path for ages four through eight. Retain ages nine through eighteen, but disable generation until reviewed packs exist.

Why: the age-eight boundary now has Grade 2 source coverage and its own acceptance fixture, while growth-ready data still must not imply untested placement or curriculum coverage.

Change later: D3 -> add a sourced and accepted age-nine pack

Agent-defaulted · confirmed

D4 — Deterministic generation contract

Use a specified seeded PRNG, generator versions, finite-capacity checks, immutable worksheet documents, and typed answers.

Why: the same request must reproduce the same content, while impossible requests must fail rather than quietly lower quality.

Change later: D4 -> retain only the seed, not a generator version

Agent-defaulted · confirmed

D5 — Defensive local storage

Use strict validation, bounded regular-file reads, ETag preconditions, a save mutex, atomic replacement, and explicit recovery backups.

Why: a local tool still needs to protect hand-edited data, stale tabs, interrupted writes, and unsafe file targets.

Change later: D5 -> omit the recovery flow from a future simplified edition

Agent-defaulted · confirmed

D6 — Exact worksheet behavior

Lock capability gates, variants, answer semantics, decoration boundaries, and neutral interest fallbacks for all four families.

Why: generators and acceptance tests need concrete educational invariants rather than broad prompts.

Change later: D6 -> move Count, Compare & Make to a later release

Agent-defaulted · confirmed

D7 — Progressive worksheet controls

Show simple defaults first, with advanced difficulty, length, answer-key, paper, and scale controls; confirm stretch changes.

Why: fast routine use and deliberate customization should coexist without surprise difficulty jumps.

Change later: D7 -> expose paper size only in print preview

Agent-defaulted · confirmed

D8 — HTML-first printable output

Use semantic HTML/CSS for Letter and A4, with accessibility, cross-platform DOM/PDF geometry, page-count, and scoped physical-print checks.

Why: one renderer keeps browser preview and paper aligned while preserving selectable, accessible text; geometry gates avoid untrustworthy cross-OS pixel baselines.

Change later: D8 -> support Letter only in a reduced edition

Agent-defaulted · changed & confirmed

D9 — Pinned stack and one original-work license

Use Node 24, React 19, Fastify 5, Vite 8, strict TypeScript, and Vitest/Playwright. One root MIT license covers all project-original code, templates, documentation, and line art.

Why: the verified versions form one reproducible local/CI toolchain, while one original-work license keeps public reuse and contribution terms simple. Future third-party materials retain their own recorded terms.

Change later: D9 -> revisit the original-work license before a future major version

Agent-defaulted · confirmed

D10 — Gated delivery

Build through thirteen automated vertical steps, then perform physical-print, real-family, and live-CI gates.

Why: correctness, privacy, print quality, and actual usability need distinct evidence before a public release.

Change later: D10 -> combine automated Steps 10 and 11

Build roadmap

  1. Foundation
    Runnable React/Fastify shell, pinned toolchain, CI, licenses, and privacy-safe ignores.
  2. Profiles
    Secure local config contract and accessible parent setup.
  3. Worksheet core
    Deterministic generation and the four worksheet vertical slices.
  4. Personalization
    Reviewed line art, interests, names, options, and answer keys.
  5. Quality
    Print/pagination matrix, accessibility, and compiled real-pipeline smoke.
  6. Release
    Public docs, physical prints, family pilot, push, and exact-commit CI smoke.

The canonical plan.md expands this roadmap into thirteen independently gated automated steps plus M1–M3 manual acceptance gates.
