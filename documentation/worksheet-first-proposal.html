Why this shape

What the UAT survey found underneath the controls.

  • 3profile fields copied into every request (writing mode, presentation band, math skills)
  • ×0.75 / +25%hidden Difficulty rescaling of every math maximum
  • 1silent mode switch: Confidence turns an equation-ready Wow into quantity mode
  • 0lines of migration code today

Today's work lives in the child

The generation boundary reads the writing mode, the vocabulary band and every math limit from the stored profile, so trying Copy a Sentence today and Picture Labels tomorrow means editing the child twice. Decorative art also rides on the unrelated "use reviewed interests" content checkbox.

Editing the file in place is the dangerous path

A shipped build that cannot strictly read a version 1 file calls it invalid and offers backup-and-replace, which rewrites the file as defaults plus one profile. A real version 2 makes every older build block with a visible, non-destructive "unsupported version" instead. That is why Step 15 bumps the version and Step 14 first freezes the version 1 reader.

Same choices, same worksheets — proven

Step 14 captures a content fingerprint of Practice-level worksheets from 5c22159 with a committed script. Every later gate reproduces it through the new path, so removing Difficulty and profile capabilities cannot quietly change what a child gets for equivalent choices.

After the upgrade, each child's old writing mode, vocabulary and math values pre-fill any choice you have not touched (D10). No control turns it back on; the old values stay in the file, read-only, and are never deleted.

Risks worth knowing

What could bite, and the built-in answer.

  • Step 15 or Step 16 runs out of iterations, and the halt parks everything after it (P7).D-split and D26 moved the refactor and the spec routing into Step 14, so each step carries only intended changes. No budget extension.
  • Real family text reaches screenshots, traces or reviewer prompts.The mandatory pre-run gate keeps the real file out of the main checkout (D-pregate, D43); agents never open main-checkout failure artifacts.
  • Your retained UAT store is lost or rejected at its first upgrade.The launcher stays stopped for the whole run; the recommended WF-0 backs the store up before you first open any build from these plans against it; WF-1 happens only after the whole run, on the last shipped build, and you keep the .v1-…bak.
  • A halt leaves an interim build in the main checkout.Never launched against real data; a halt after Step 14 still reads and writes version 1 exactly as today, and from Step 15 the saved shape is already final.
  • Runtime reviewers only see the empty landing page.Each of Steps 16–19 says what that screenshot can confirm and which compiled specs prove the rest; a fictional-data exercise script remains the D29 tweak.
  • A saved Confidence or Stretch quietly changes a child's range.The upgrade notice says it no longer applies and each focus uses exactly its stated range; the backup keeps the old value (D16).
  • Untouched controls change when a migrated child is selected.Only untouched groups move, a status line explains, and the first explicit defaults save ends it (D10).
  • Unsaved choices vanish on a browser page reload.By design under P1: no browser storage; the save action sits beside Create, and in-app reloads keep choices.
  • Plan 02 or 03 widens a saved value in place.The fingerprint and the contributing rule force version 3 with a version 2 reader (D9).
  • An old tab or an oversize upgrade tries to write.A stale tab's version 1 body gets 422; an upgrade over 64 KiB gets 413 before any backup. The file is unchanged either way.
