Two cost sources

(a) Plan content

  • Full check as every step's DONE gate in a fresh worktree. The skills require only typecheck, lint and test; the plans made the gate build + Vitest + compiled Playwright + calibration, and the skills then run it up to four times.
  • release:verify per step: 4 + 3 + 4 clean-room runs.
  • Evidence files, per-file test listings, consumer tables, grep-hit verdicts.
  • Golden captures and freezes: plan 01's compare at every gate, plan 02's second capture system, plan 03's documents-builder sweeps.
  • Guards: module-graph, three fingerprints, copy scan, title guard, docs scan, literal scans, version pin, request mirror, depth-bound quadruplication, standing checks S1–S8.
  • Calibration demanded on every evidence row; right for measurement tools, wasted on wording and import scans.
  • Schema bumps forced by the fingerprint rule (plan 02 Steps 22–23; plan 03 Step 28).
  • Three plans, 132k words, for one product iteration.

(b) Pipeline ceremony (workflow settings)

  • Orchestrator re-runs typecheck/lint/test after the developer already did, every iteration (build-step Step 4).
  • build-step post-merge full suite and build-phase §2f full suite, back to back.
  • full lane = 8 reviewers with a dev-server lifecycle; --ui starts the server even for deep. "NOT OBSERVED counts as medium" pushes landing-page steps to an extra round.
  • Fixed one-line checkpoint message and shell-forwarded --acceptance caused D-pointer, D38, D-scripted-evidence.
  • Test-count regression as a halt class caused D23's pair-every-deletion rule.
  • Default --max-iter 3 drove step splits (D-split, D41, D50).

Rule of thumb: anything whose justification cites build-step or build-phase behavior is pipeline ceremony leaking into the plan. Fix the pipeline once.

Per-step settings

  • --reviewers code --isolation worktree for all steps. Runtime reviewers only with a committed fictional-data exercise script that shows the feature.
  • Developer and orchestrator iterate on the narrow suites the step names. One full npm run check per step, post-merge, owned by build-phase §2f.
  • release:verify once per plan, inside /repo-update.
  • At most 6 Done-when items per step, each naming behavior and its test file. Calibration only for print geometry and log privacy. No evidence file.
  • Iteration budget stays 3. Run plan by plan with the operator's screen review between plans.

  • P7 one unattended chain over three plans → plan by plan, since a halt anywhere parks everything and the operator has not yet seen Step 17's panel.

What was adopted on 2026-09-30

The operator instructed that the proposed changes be incorporated. The record lives in documentation/feature-seeds/operator-decisions.md under "Lean revision", and each plan carries a precedence block under its title.

New operator choices

  • P9. Packets are a session-only queue in React state; closing or reloading the page loses it, and the panel says so. Supersedes P4.
  • P10. Plans build one at a time, each followed by /repo-update and the operator's screen review. Supersedes P7's single chain; P8 unchanged.

Lean-revision rulings

  • Plan 01 builds 17, 18, 19; plan 02 builds 24, 25, 26 and optionally 27; plan 03 builds 31 and 33. Dropped steps keep their headings and issue numbers with Status: SKIPPED.
  • Every kept step: --reviewers code --isolation worktree; one full gate per step; release:verify once per plan.
  • Step 18 adds the blocked classifier state; additive fields land at schemaVersion 2; no v3, no packet store.
  • No evidence files, ledgers, capture compares, new AST/grep guards, fingerprint re-pins, or new smoke projects. One release-smoke case per feature. Known vectors inline.
  • Single pre-run item: ports free, launcher stopped, config file absent (metadata check).
  • Issues #31–#34 to be closed as superseded at their plan's /repo-update; plan 03 syncs issues for Steps 31 and 33 only.
